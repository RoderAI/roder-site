## What changed

Roder 0.1.18 adds a built-in review workflow for people who want a second pass over a change without giving the reviewer permission to edit the workspace. The new `/review` command starts a detached review turn over uncommitted changes, a base branch, a specific commit, or a free-form scope. That child turn gets a review rubric and a read-only tool allowlist, then returns structured findings with priorities, confidence, and file/line locations.

The terminal UI now opens completed findings in a review panel. Every finding starts selected, so you can drop weak or irrelevant comments before publishing. The parent thread also receives a synthetic review summary, which means a later instruction such as "fix the P1s" can refer to the review without making the review agent itself responsible for changing code.

The same flow is available to clients through `review/start`, `review/publish`, and `review/publishers/list`. Notifications cover the lifecycle with `review/started`, `review/completed`, `review/failed`, and `review/published`, so a desktop, IDE, or CI client can keep review work detached while still showing progress.

## Why it matters

- You can ask for a careful review before committing or opening a pull request without handing the reviewer write tools.
- Findings are structured enough to render in product UI, filter by severity, and publish selectively instead of treating the model's answer as an undifferentiated note.
- Review output stays attached to the requesting thread, so the main agent can fix accepted findings after the review finishes.
- The publisher contract is extension-based. GitHub is included first, but the core API does not need to change for another review destination.
- `roder app-server` now uses a multi-threaded Tokio runtime, which keeps providers that bridge synchronous callbacks into async work, including the Claude Code provider, from aborting the server on tool calls.

## Using it

Run `/review` from the TUI:

```text
/review
/review --base main
/review --commit a1b2c3d
/review check the retry loop and error handling
```

Use the review panel to keep or drop findings, then publish the kept set when a publisher is configured. `--publish <id>` preselects a publisher for the panel; it does not post comments by itself.

For GitHub pull request comments, configure the first-party publisher:

```toml
[review]
default_publisher = "github"

[review.publishers.github]
mode = "auto"
event = "COMMENT"
min_priority = "p2"
token_env = "GITHUB_TOKEN"
```

`dryRun: true` on `review/publish` returns the payload that would be sent to GitHub without making a network write. Roder also prefilters findings against pull request diff hunks, so one unmappable line does not cause GitHub to reject the entire review.
