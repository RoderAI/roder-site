## Keep the page you are working on

Successive `jev_browse` calls in one thread now share their Chrome session. An empty `url` continues the current page; a supplied URL navigates in the same tab. The `tab` argument selects `current`, `new`, `reset` or `close`, with at most three tabs retained. Cookies, page state and recent call context survive between calls.

Results now include a bounded page digest, action effects, headings and available controls, so the calling agent can inspect what happened instead of receiving only a short status line. Access-denied pages are reported before decisions are attempted. A `done` result still needs to be checked against the goal and the observed page.

## Recover when Jev cannot continue

`JEV_FALLBACK=auto` runs a bounded full-browser loop on the same tab when Jev stalls or runs out of suitable actions. The result separates Jev's outcome from the fallback driver's work. Choose `handover` to return control to the caller through `jev_tab_*`, or `off` to disable fallback. Missing input, confirmation requests and access denial do not trigger it. Origin restrictions, approvals and secret handling continue to apply.

## Optional browser-use MCP server

Start `roder --browser-use`, or enable `[browser_use]`, to expose `browser_use_*` tools through the pinned local stdio MCP server. Roder launches it on first use with a visible browser by default; `headless = true` hides it. This path needs `uvx` and the server's dependencies. Default policy asks for approval for browser input, while Plan mode denies it. Server shutdown cleans up its process group, including browsers it started.
