## Request only the history a client needs

The new `thread/history/read` API returns chronological item pages with opaque exclusive cursors, item and byte budgets, and complete turn metadata. Clients can request bounded portions of a long conversation instead of loading its entire snapshot.

The local JSONL store maintains a derived seek and projection index. Warm page reads deserialize selected items, while index updates preserve streamed deltas and terminal outcomes. Older logs rebuild this disposable index one committed record at a time.

## Handle unsupported stores explicitly

A store without paging support reports that missing capability rather than silently loading the full conversation. Generated method manifests expose the API to SDK consumers.

See the [app-server protocol](/docs/app-server/), [sessions](/docs/sessions/) and [SDK guide](/docs/sdk/) for client integration.
