## Work beyond a browser tab

Roder adds opt-in Cua Driver tools for discovering apps and windows, screenshots, grounded clicks and drags, scrolling, keyboard input, Unicode replacement and browser interaction. On a provisioned XFCE/X11 Blaxel desktop, an agent can work with files, LibreOffice Writer and Chrome, while a read-only loopback viewer lets you watch.

Enable the runner backend only after provisioning a graphical session with the pinned Cua Driver:

```toml
[cua]
enabled = true
backend = "runner"
```

Bind the thread to that sandbox. Select `backend = "local-macos"` explicitly for the signed local CuaDriver app, with the required macOS permissions. Existing browser profiles remain disabled by default and require a separate trusted driver launch grant as well as configuration opt-in.

## Boundaries and archive compatibility

Approvals, Plan-mode observation and thread/runner isolation still apply. New input invalidates old grounding, and uncertain input is not replayed. X11 is the qualified Linux target; Wayland, personal browser accounts and macOS browser attachment are not established by this release's validation.

The original 0.3.5 Linux archives require GLIBC up to 2.39. **Use 0.3.6 or newer for the Ubuntu 22.04 / GLIBC 2.35 baseline.** The 0.3.5 archives remain unchanged. The macOS archive passed the release's signing and startup checks.
