## What changed

Roder 0.1.19 improves long Grok runs on the `xai` and `supergrok` providers. When Grok returns a maximum-prompt-length or related context-overflow error, Roder now classifies it as a context-limit failure instead of a generic provider error. The active turn can force a compaction, retry in place, and, if the first retry still carries too much bulk, make a second attempt with the last oversized item stripped from the request.

The compaction path is also more defensive. Summary inference uses a smaller head so the summary request itself is less likely to overflow, and if even that fails, Roder falls back to a deterministic summary. That gives the next model call a usable compact boundary instead of leaving the thread stuck behind a failed summarization attempt.

Grok model catalogs now advertise `xhigh` reasoning alongside the existing lower efforts. That applies to the xAI API-key provider and the SuperGrok OAuth provider, so long-horizon, tool-heavy Grok workflows can select a stronger reasoning setting directly from Roder's normal model controls.

## Why it matters

- Long Grok threads can keep moving after context growth instead of failing at the exact moment a compact-and-retry would have been useful.
- A failed summary request no longer turns compaction into another blocker; deterministic fallback keeps the transcript recoverable.
- SuperGrok and xAI users see the same `xhigh` reasoning option in Roder's catalog, making provider choice less surprising.
- The retry happens on the live turn, so the user does not need to manually compact, re-run the prompt, or reconstruct what the agent was doing.

## Using it

Select Grok through either provider:

```sh
export XAI_API_KEY="..."
RODER_PROVIDER=xai RODER_MODEL=grok-4.5 RODER_REASONING=xhigh roder
```

```sh
roder auth login supergrok
RODER_PROVIDER=supergrok RODER_MODEL=grok-4.5 RODER_REASONING=xhigh roder
```

For ordinary short turns, no setup change is required. The overflow recovery path runs when Grok reports a prompt-length or context-window failure, then records the compacted context boundary in the thread history before continuing.
