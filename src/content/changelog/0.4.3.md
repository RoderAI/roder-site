## Keep completed output from the stream

Roder retains completed streamed output when a terminal response omits its output items. A sparse final response therefore does not erase work already received during streaming.

## Send only the missing continuation context

WebSocket continuations now account for reasoning, assistant messages and tool calls that the provider already holds. Roder avoids sending those items again alongside `previous_response_id`, preventing duplicate model history during a continuing conversation.

This is a Responses continuation fix; no configuration change is required. See [providers](/docs/providers/) for the supported inference integrations.
