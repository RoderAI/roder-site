## What changed

Roder 0.1.22 fixes the DeepSeek Platform provider so thinking-mode models behave like first-class Roder reasoning models again. DeepSeek entries advertise their supported reasoning efforts in the model picker, so Ctrl+P can show the thinking choices that the provider accepts instead of flattening them into an ordinary chat selection.

When thinking is enabled, Roder sends DeepSeek's explicit `thinking` toggle and maps the selected Roder reasoning effort onto the provider request. Streaming `reasoning_content` is handled as reasoning output, separate from final assistant text. If a DeepSeek turn calls tools, Roder also carries the reasoning content back on the assistant tool-call message where DeepSeek expects it.

## Why it matters

- DeepSeek users can select thinking behavior from the same provider/model controls they use for Codex, Grok, Cursor, and other reasoning-capable providers.
- Tool-heavy DeepSeek rollouts keep their reasoning context intact instead of losing the chain between the model call, tool results, and the next assistant step.
- Reasoning streams appear in Roder's reasoning timeline rather than leaking into final answer text or disappearing entirely.
- Existing `DEEPSEEK_API_KEY` setup keeps working; this release changes provider correctness and TUI ergonomics, not credentials.

## Using it

Select DeepSeek Platform and a thinking-capable model:

```sh
export DEEPSEEK_API_KEY="..."
RODER_PROVIDER=deepseek RODER_MODEL=deepseek-reasoner RODER_REASONING=high roder
```

Inside the TUI, open the provider/model picker with Ctrl+P and choose a DeepSeek model with the reasoning level you want. Use `deepseek-chat` when you want the non-thinking chat alias, and use `deepseek-reasoner`, `deepseek-v4-flash`, or `deepseek-v4-pro` when the task benefits from DeepSeek thinking mode.
