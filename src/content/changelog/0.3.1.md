## One owner for durable runtime writes

Hosting services can enable tenant-scoped ownership leases with database-clock expiry and increasing generations. Expired or superseded owners cannot renew or release their replacements. Session, checkpoint, event and artifact writes are fenced inside owner-locked transactions, preventing an old replica from continuing to write after ownership changes.

An optional execution lease also stops admission of turns and tools after authority is lost, rechecks after approval waits and closes stale hosted sockets. Renewal supervision revokes local authority on loss or uncertainty. Actions already dispatched to an external system still require host-level reconciliation after a crash.

## Drain with a confirmed handoff

Idle-owner sealing waits for admitted turns, tool work and cleanup before attempting bounded durable release. Replica draining rejects new work and accounts for forwarded sockets, so an empty local runtime pool alone does not mean the replica is drained. Hosts should stop inbound work and treat only confirmed release as the handoff receipt.

Authenticated one-hop forwarding requires a trusted owner endpoint and shared replica authentication policy. An optional same-port HTTP lifecycle handler exposes rollout controls; it is disabled by default. Embedders must update the changed hosted options, session-store and MySQL configuration APIs. Standalone users do not need to enable these hosting features.
