## What changed

Roder 0.1.17 upgrades the Parallel.ai web-search integration from a search-only router backend into a richer web-access tool provider. Parallel search now matches the current V1 API shape, including `advanced_settings` for result limits, domain include/exclude filters, location, and mode. Existing `web_search` calls keep using Roder's canonical search interface when Parallel is selected.

The release also adds `parallel_extract`, a focused URL extraction tool. A turn can search for candidate sources first, then extract one or more known URLs into clean markdown excerpts or bounded full-page content. Extract requests accept `url` or `urls`, an `objective` or `query`, optional `search_queries`, content limits, and a `session_id` from a previous Parallel search when continuing the same investigation.

When Parallel is the configured web-search provider, Roder now installs the Parallel tools automatically and appends concise developer instructions to the turn. Those instructions tell the model to search first, extract the best URLs when it needs deeper page content, prefer Parallel tools over shell fetches for public web pages, and cite URLs when making factual claims.

## Why it matters

- Research turns can move from discovery to source inspection without leaving the tool system. The model can find relevant pages, then pull focused markdown from the best URLs instead of relying only on snippets.
- Parallel's current API fields are mapped directly, so result counts and domain filters behave as configured instead of silently being sent in an outdated shape.
- The canonical `web_search` surface still works for product clients that do not want provider-specific schemas, while namespaced tools can expose `parallel_search` and `parallel_extract` when a workflow needs them.
- Prompt guidance is automatic when the tools are present, which makes web-enabled runs more consistent without requiring every user or host to hand-write search/extract instructions.

## Using it

Configure Parallel as the web-search provider:

```toml
[web_search]
enabled = true
mode = "external"
provider = "parallel"

[web_search.parallel]
enabled = true
api_key = "..."
# mode = "advanced"
```

You can also provide the key through the environment:

```sh
export PARALLEL_API_KEY="..."
roder
```

In a web-enabled turn, ask Roder to research a topic or inspect specific URLs. Roder can call `web_search` or `parallel_search` for discovery and `parallel_extract` when it needs deeper content from selected sources. Extraction supports up to 20 HTTP(S) URLs per call and lets the turn bound total and per-result content so long pages do not overwhelm the context.
