## What changed

Roder 0.1.20 makes Ultra a runtime mode instead of tying proactive multi-agent behavior only to Sol and Terra's Ultra reasoning effort. The TUI now accepts `/ultra`, `/ultra on`, `/ultra off`, `/ultra status`, and `/ultra <prompt>`. Persistent mode applies to subsequent turns in the thread, while the prompt form runs one task with an Ultra reminder without flipping the persistent toggle.

When Ultra mode is active, Roder injects the proactive multi-agent policy into the turn's developer instructions. The visible transcript still contains what you typed; the runtime supplies the delegation policy behind the scenes. That means Grok, Claude, Luna, Cursor, Kimi, DeepSeek, and other models can be encouraged to spawn teammates when parallel work would materially improve the result, even if the model does not expose an `ultra` reasoning effort.

Sol and Terra keep their existing Ultra reasoning behavior. Selecting Ultra effort still maps to the provider's `max` wire effort and enables proactive multi-agent delegation. The new mode composes with that behavior: use Sol/Terra Ultra when you want the strongest reasoning effort, or use `/ultra` with any model when you want proactive teammate use without changing reasoning effort.

The release also fixes child selection for `task` and `agent_swarm`: children inherit the parent thread's live provider and model by default. A SuperGrok parent therefore keeps Grok 4.5 children unless the request explicitly asks for a compatible override. For large fanouts, lane `max_concurrent` can now be raised per request, capped by the dispatcher's global safety limit, instead of failing at the older lane default.

## Why it matters

- Ultra is now a workflow control, not just a Codex model effort. You can use proactive delegation with the provider/model you are already using.
- The TUI shows Ultra in the active mode label, so it is visible when a thread is allowed to delegate proactively.
- App-server and SDK clients can toggle the same state with `thread/set_ultra_mode`, read it from `settings/get.ultraMode`, and listen for `ultra/modeChanged`.
- Subagents and swarms preserve the parent provider/model more predictably, which avoids accidental fallback to another model during delegated work.
- Larger fanouts can ask for more lane concurrency when the user explicitly wants many parallel children, while runner lanes and global caps still bound execution.

## Using it

From the TUI:

```text
/ultra on
/ultra status
/ultra audit this change with parallel reviewers
/ultra off
```

From an app-server client:

```json
{
  "method": "thread/set_ultra_mode",
  "params": {
    "threadId": "thread-123",
    "enabled": true,
    "trigger": "manual"
  }
}
```

Use Ultra when the work benefits from parallel investigation, implementation, or verification. It does not change sandbox, policy, approval, workspace, or credential boundaries; child agents still run through the normal Roder tool and policy paths.
