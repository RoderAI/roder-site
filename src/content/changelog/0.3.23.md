## Ask for a reminder or recurring check

Agents can subscribe to named topics, schedule a one-shot reminder or recurring check, inspect the next delivery, and cancel a watcher when its work finishes. A follow-up retains the conversation context and waits until the thread is idle before running.

Use this for a requested check that belongs to the current task, such as watching CI until it reaches a terminal state. Stop the subscription when the requested work is done.

## Choose the right scheduling lifetime

These subscriptions live in the running harness. They are not durable independent jobs and do not survive harness exit. Use app-server automations when a schedule needs an independent, durable lifetime.

This release also fixes Codex follow-up context roles and Cursor MCP integer arguments so scheduled turns work through both live provider integrations.

See the [event bus](/docs/event-bus/) for subscription tools and [app server](/docs/app-server/) for durable automation.
