## Desktop tools on a supported Linux baseline

Roder 0.3.6 includes the Cua computer-use feature and corrects the Linux archive compatibility problem in 0.3.5. Both Linux architectures are built in a pinned Ubuntu 22.04 environment with a GLIBC 2.35 baseline. Release gates check library requirements, startup and disabled/enabled Cua registration before packaging.

The 19 opt-in tools cover app/window discovery, real screenshots, grounded input, window controls and browser actions. They support a provisioned XFCE/X11 Blaxel desktop, including file navigation and Writer documents, or an explicitly selected local macOS backend using the signed driver app.

## Set up the desktop first

Provision the graphical runner with Cua Driver 0.34.0, enable `[cua]` with `backend = "runner"`, and bind the thread to that sandbox. Use `local-macos` explicitly for the local signed app and grant its macOS permissions. Browser profile reuse needs separate opt-in and a trusted launch grant. These tools do not provision a desktop merely by being enabled.

Approvals and grounding checks remain active. X11 is the validated Linux target; Wayland, personal browser accounts and macOS browser attachment remain unqualified. The container fixture's Chrome flags are not a production browser policy.

## Install and verify

Upgrade with `brew upgrade roder` on Apple Silicon, or download the matching Linux archive and verify its SHA-256 sidecar. The release notes link the published archive, signing, ACP startup and rolling-installer verification reports. Prefer this version over 0.3.5 on Ubuntu 22.04; no workaround for the older archive is needed.
