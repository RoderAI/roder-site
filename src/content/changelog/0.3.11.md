## Keep related turns together

Every OpenRouter request now carries a sticky routing key. Roder uses the runtime prompt-cache key when available, otherwise the turn's thread ID, and sends it as both `prompt_cache_key` and `session_id`. The session value respects OpenRouter's 256-character limit.

This gives OpenRouter the information it needs to route a conversation consistently from the first request, instead of scattering early turns across upstream providers with cold caches. It is especially useful for coding sessions that repeatedly send a shared repository and conversation prefix.

## No manual cache-key setup

The key is supplied automatically and works alongside the routing controls introduced in 0.3.10. Existing threads do not need a migration or a manually maintained session identifier. Cache hits and savings still depend on the upstream provider and the content of the requests; a stable routing key is not a guarantee of a cache hit.
