## Make routing match your workflow

OpenRouter requests now sort upstream providers by price by default. Configure `[providers.openrouter.routing]` to replace that default, or use `[providers.openrouter.model_routing."<slug>"]` for a model-specific policy. You can pin providers, disable fallback, set price ceilings or sort by latency or throughput.

For example, a workload that needs a particular upstream can use:

```toml
[providers.openrouter.model_routing."your/model-slug"]
only = ["deepinfra/fp8"]
allow_fallbacks = false
```

Replace the slug and provider with a route supported by your model. An empty `routing = {}` restores OpenRouter's own load balancing rather than the price-sort default. Strict pinning deliberately limits the available fallback options.

## Request a service tier

Set `service_tier` under `[providers.openrouter]` to request `flex`, `priority` or `ultrafast`. Runtime per-request tier overrides now reach OpenRouter too. The setting is sent to the provider; availability and actual service remain subject to that provider.

Existing users get the new price-based default without editing configuration. Review routing if your workflow depends on a specific upstream, latency target or fallback policy.
