## Connect an ACP session to its tools

ACP clients can inject stdio or streamable HTTP MCP servers and send image prompts. Restoring an existing session restores matching tool bindings, so the resumed conversation can use the tools associated with that session.

Stdio MCP clients accept a working directory. HTTP MCP clients expose explicit session shutdown, and MCP connections close when their session closes or the CLI shuts down orderly.

## Keep controls scoped to the session

Clients can list saved sessions, select models and persist session-specific permission modes. Paseo host instructions become thread developer instructions. Native `thread/state` and `thread/set_mode` also accept an optional `threadId` for scoped mode access.

These additions let an ACP host manage a conversation's inputs, tools and controls through the bridge. See [ACP](/docs/acp/), [MCP integrations](/docs/mcp/) and the [app-server protocol](/docs/app-server/) for the related interfaces.
