## Authenticate from an ACP client

Fresh ACP installations now use Codex instead of mock inference. When Codex is selected, an ACP client can request browser sign-in through `authenticate`. Existing configured providers and models remain in use, and initialization reports the CLI release version.

## Reconnect to saved conversations

ACP supports loading a session with history replay, resuming without replay, and closing a session after draining its turn and releasing live resources. Reconnection validates the session workspace and preserves the stored conversation. Closing also cancels pending permission callbacks. Native clients gain `thread/unload`.

See [ACP](/docs/acp/) and the [app-server protocol](/docs/app-server/) for integration guidance.

## Install the native CLI through npm

The native CLI is packaged as `@roderai/roder`. Versioned CLI releases publish the npm package after installation checks pass on supported targets, giving npm users another installation route.

Follow the [installation guide](/docs/install/) for current commands.
