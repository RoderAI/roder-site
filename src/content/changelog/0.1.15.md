## What changed

Roder 0.1.15 fixes the OpenCode provider path for longer DeepSeek-backed coding turns. The built-in OpenCode Zen catalog now removes the disabled free DeepSeek ids and exposes the current free Zen models plus the paid `deepseek-v4-flash` and `deepseek-v4-pro` entries. Both OpenCode Zen and OpenCode Go can use the paid DeepSeek routes.

The release also changes how Roder serializes tool-heavy chat-completions history for OpenCode. When a model emits parallel tool calls, Roder now groups those calls into one assistant `tool_calls` message and pairs every tool-call id with the matching tool result before the next assistant step. That keeps multi-step DeepSeek rollouts inside the OpenAI-compatible invariant expected by OpenCode's gateway.

Provider failures are easier to act on too. OpenCode `ModelError` and `CreditsError` details now surface in the Roder error text instead of being buried inside a raw HTTP status/body blob.

## Why it matters

- OpenCode DeepSeek runs can keep using tools across several steps instead of hitting avoidable `400 invalid_request_error` failures once the conversation includes parallel tool results.
- The model picker no longer points people at disabled free DeepSeek model ids. Free Zen users see the current free catalog, while paid DeepSeek users can select the supported flash or pro routes deliberately.
- Failed setup is clearer. A disabled model, missing payment method, or other OpenCode-side problem now reads like a provider error the user can fix, not an opaque transport failure.
- Existing OpenCode API-key setup remains the same. This is a provider reliability and catalog refresh, not a new credential flow.

## Using it

Configure OpenCode as before:

```sh
export OPENCODE_API_KEY="..."
RODER_PROVIDER=opencode RODER_MODEL=deepseek-v4-flash roder
```

Use `opencode` for Zen and `opencode-go` for the Go surface. Current Zen free models include `big-pickle`, `mimo-v2.5-free`, `nemotron-3-ultra-free`, and `north-mini-code-free`; paid DeepSeek users should select `deepseek-v4-flash` or `deepseek-v4-pro`.

For troubleshooting, read the provider error literally. A `ModelError` usually means the selected model id is unavailable for that OpenCode surface. A `CreditsError` points at billing or payment setup for the account behind the API key.
