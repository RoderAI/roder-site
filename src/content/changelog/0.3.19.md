## Count the work across inference rounds

Configured task agents now accumulate the final usage snapshot from every inference round. A task that asks the model to work again after a tool result therefore retains the earlier rounds instead of showing only the last one. Runtime turns count cumulative streaming snapshots once, preserving input, output, cache-read and cache-write tokens together with reported service-tier information.

This makes usage history more useful when reviewing long tasks and delegated work: the recorded totals reflect the provider usage Roder actually observed throughout execution.

## Preserve usage through errors and interruption

A provider failure, stream error, deadline or user interruption no longer discards known usage from the unfinished turn. Interrupted-turn usage is carried through saved history, app-server notifications and local analytics. You can stop a task and still inspect the usage it reported before stopping.

Thread usage metadata is saved before terminal notifications are sent. Repeated handling of a terminal event cannot charge the same usage twice, and native compaction during an active turn is included once in terminal accounting. No configuration change is required. Roder cannot reconstruct tokens a provider never reported, so incomplete provider reporting remains a limit of these totals.

See [usage analytics](/docs/usage-analytics/) for the existing local reporting and export commands.
