## Keep embedded runs in their own data area

Hosts embedding Roder can set `DefaultRegistryConfig.data_dir` to choose the directory used for memory, knowledge, the code index and default threads. This lets a desktop application or another local host keep its runs separate from the person's normal Roder data and recall context.

The same registry configuration gains `memory`, `knowledge` and `code_index` switches. All default to enabled; a host can disable the services it does not want to register rather than inheriting every recall subsystem.

## Update host configuration code

These are Rust embedding options, not new CLI flags. Applications constructing `DefaultRegistryConfig` with exhaustive struct literals must add the fields and rebuild against the updated dependent packages. Decide the data directory and enabled services when constructing the registry.

Normal CLI workflows retain the defaults. The release does not automatically move existing data into a new location; isolation is an explicit host configuration choice.
