## Native actions on an explicitly bound browser

The CLI now includes the native OpenAI Responses computer tool for explicitly bound Chrome sessions. Browser observations, action results and completion handling travel through the same Roder runtime, giving supported models a native route to act on that browser.

## Reuse sessions without stuck input

Cancelled cached sessions are reconciled before reuse. If releasing a key or mouse button failed, Roder retries cleanup, and attempts each release and screenshot-mask cleanup independently. This reduces the chance that one cleanup failure leaves the next action with a held modifier or stale session state.

Desktop origin and tab settings are validated. Origin scope is checked before resolving a target, and arbitrary evaluation is disabled under an origin ceiling. Secret scrubbing covers overlapping values and nested observations. These changes make browser reuse more predictable while retaining the configured access boundary.

Custom integrations also gain more tolerant handling of documented empty Jev completion conditions and sparse controls. The configured evaluation endpoint is honored, and native compaction validation is included in the release.
