## Request Ultrafast from your OpenAI provider

You can now set a default service tier in your Roder configuration:

```toml
[providers.openai]
service_tier = "ultrafast"
```

This requests Ultrafast processing for OpenAI API calls without adding a tier to every request. Generated remote app servers receive the setting too, so moving work to a remote runtime preserves the configured default. Availability still depends on the provider and model; a requested tier does not guarantee access or latency.

## Give each conversation its own default

App-server clients can pass `serviceTier` to `thread/start` and change an existing thread with `thread/set_service_tier`. Thread read and list results expose the saved value, it survives server restarts, and conversation forks inherit it. This lets a client keep a preferred tier for one conversation while other work uses the provider default.

Pass `serviceTier` to `turn/start` for a one-turn override. The order is turn override, thread default, then provider configuration. Use `"default"` for standard processing on one turn, or send `serviceTier: null` to `thread/set_service_tier` to clear a thread default. Changing the default does not alter a turn already running. Both TypeScript and Python SDKs expose creation defaults, turn overrides and a thread setter.

See [provider configuration](/docs/providers/) and the [app-server guide](/docs/app-server/) for setup.
