## What changed

Roder 0.1.23 fixes multiline entry in the terminal UI composer. Shift+Enter now inserts a newline instead of submitting the prompt, so longer instructions can be shaped in the composer before the agent sees them.

The release also improves terminal compatibility under tmux. When Roder detects a tmux pane that cannot distinguish Shift+Enter from Enter, it enables CSI-u extended key reporting and respawns the pane once when needed. That lets terminals such as Ghostty report the modified Enter key as a distinct event. For terminals that still cannot report the modifier, Roder accepts Ctrl+J and Alt+Enter as newline fallbacks.

## Why it matters

- Multi-paragraph prompts, pasted checklists, and structured instructions can be composed safely before submission.
- Enter remains the fast submit path, while Shift+Enter is reserved for editing the current prompt.
- tmux users get the same behavior as direct terminal sessions when the terminal and pane support extended keys.
- Ctrl+J and Alt+Enter keep multiline input available in more terminal setups, even when Shift+Enter cannot be distinguished.

## Using it

In the TUI composer:

```text
First paragraph of the instruction.
Shift+Enter
Second paragraph, checklist, or context block.
Enter
```

Use Ctrl+J or Alt+Enter if your terminal does not emit a separate Shift+Enter event. No configuration change is needed for ordinary Ghostty sessions. Inside tmux, Roder enables the required modified-key mode for the active pane when it can.
