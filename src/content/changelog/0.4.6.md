## Read the result after a page responds

Roder 0.4.6 brings the browser improvements ported from fastbrowse into the distributed CLI. After an input starts a fetch or XHR request without a visible page change, Jev waits for the response and rendering within its existing bounded settle time. This helps avoid reading stale results and pressing the same control again while an application is still answering. Ordinary CSS class names such as `skeleton-layout` no longer force an unnecessary loading delay.

Page observation scripts are installed once per document, with a fallback when installation is refused. Smaller observations and leaner decision requests reduce repeated browser and model work. Cross-origin frame reads use persistent sessions and a five-second deadline, followed by shorter retries after a miss, so an unresponsive embedded frame cannot consume a full long timeout on every observation. This improves reading embedded content; it does not add general control of cross-origin frame elements.

## Keep exported files as evidence

A successful export can leave the page unchanged. Jev now tracks downloads from its own tabs, waits within a bounded time for the file to finish, and reports the saved name, path, size and completion state. Small readable text files also contribute a text preview. A task that exports a CSV can therefore inspect evidence that the file arrived rather than treating the unchanged page as a failed click.

Files are saved under the temporary `jev-downloads` directory, with separate paths to avoid overwriting files that share a name. Repeated copies with the same name and content are identified and do not count as new progress. The tool result includes a “Files Jev downloaded” section. An initial URL that is itself a file, or a download in a newly opened tab Jev has not adopted, remains outside this handling.

## Spend fewer calls filling a form

For an eligible form with several empty text fields, the text helper can prepare values in one call, then reuse each value only while its field is unchanged and empty. Each field still takes its own browser decision and action checks. Actions that may submit the form discard unused prepared values, allowing the next attempt to use the application's response.

Forms containing passwords or one-time codes keep the single-field path. Missing values are not permission to invent contact details. This reduces repeated value-generation work in ordinary contact and booking forms without changing the browser setup or bypassing the existing gates.

## Recover from temporary pages and check commitments

Jev can wait for recognized self-clearing interstitials instead of immediately treating a temporary challenge page as the final result. A real access refusal still stops the task. The opt-in irreversible-action gate now considers more commitment words, link destinations, surrounding headings and form submissions, including additional languages. Enable it for the built-in tools with `JEV_CONFIRM_IRREVERSIBLE=1`; it is off by default. With the gate enabled, new-password submissions receive an explicit check, and a goal that forbids downloads cannot be overridden by authorizing irreversible actions.

These checks improve coverage; they do not guarantee that every externally visible change is caught. Keep the task's scope explicit and verify the observed outcome. The release reports false successes falling from one to zero on its shared live corpus, roughly 11% lower decision cost, and MiniWoB++ successes rising from 83/96 to 87/96. Those are evaluation results, not a guarantee for an arbitrary website.

Upgrade the CLI to receive these changes; the existing browser and decision-provider credentials still apply. The optional confidence-based consult and light-recovery tiers remain off by default (`JEV_CONSULT_BELOW` and `JEV_LIGHT_RECOVERIES`). Full fallback remains the production policy. See [browser decisions](/docs/browser-decisions/) for configuration, download reporting and outcome verification.
