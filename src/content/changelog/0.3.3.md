## Preserve conversation state during compaction

Automatic, manual and context-limit recovery compaction now use OpenAI's native Responses mechanism for OpenAI API-key and Codex subscription sessions, including models missing from the local catalog. Roder retains the encrypted boundary and the messages that belong with it, rather than substituting a local text summary after a native failure.

Compaction waits until routing has selected the provider. This keeps Codex OAuth conversations on the provider-owned path they require, while custom Responses providers that lack native compaction can still use the local fallback.

## Better client feedback

After routed compaction, Roder completes context assembly before reporting context size. Clients therefore receive the compacted prompt size rather than an incomplete measurement. Parent-turn output constraints are cleared during compaction so they do not interfere with the maintenance request.

There is no new CLI setup step. Native compaction failures are surfaced instead of silently replacing the conversation state, giving users and embedding clients an explicit failure to handle.
