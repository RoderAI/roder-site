## What changed

Roder 0.1.24 rolls the recent local-hook and model-catalog work into the published `roder` CLI. Projects can now use Codex-compatible hook files to run local commands around sessions, prompts, tool calls, permission requests, compaction, subagents, and stop events. Roder looks for `.roder/hooks.json` first and falls back to `.codex/hooks.json`, so teams can either keep copied Codex hook configuration or maintain Roder-specific policy beside it.

The hook behavior is stricter and quieter in the places that matter for daily work. `SessionStart` now runs once for the opened thread session instead of re-running each time the thread store is read. Fresh sessions match `startup`, resumed sessions match `resume`, and repeated reads after a turn has loaded or stopped do not fire setup again. `PreToolUse` hooks can deny a tool call even when the denial reason is blank, chained hooks see the input as the previous hook rewrote it, and tool calls without matching hooks keep the model's original raw arguments instead of being needlessly re-serialized.

This release also refreshes the provider catalogs. Roder exposes Gemini 3.7 Flash, Gemini 3.8 Flash, Grok 4.6, GPT-6 Astra, and Claude Fable 5.1 across the relevant native, Cursor, Codex, Anthropic, xAI, SuperGrok, Vertex, Gemini, and OpenRouter paths. Grok 4.6 replaces older Grok 4.5 and Grok Build entries in the active catalogs, with provider-specific context windows and reasoning controls preserved.

For multi-agent work, `wait_agent` now checks the teammate mailbox directly as well as already-delivered turn steers. If a teammate message was queued before the parent started waiting, the parent can wake immediately on that pending mailbox activity instead of sleeping until timeout.

## Why it matters

- Project-local hooks can enforce repo-specific checks, add context, or block risky tools without requiring a custom Roder build.
- Session setup hooks are finally session-scoped, which keeps environment checks and logging from firing several times during one `roder exec` or resumed thread.
- Hook denials fail closed when the hook clearly denies the call, even if its message is terse or empty.
- The model picker and environment-variable workflows see the current provider catalogs without hand-editing ids or waiting for a separate extension update.
- Parent agents coordinating teammates get faster feedback when mailbox messages are already queued, so `wait_agent` behaves more like a real event wait than a blind timeout.

## Using it

Create a hook file in the workspace:

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume",
        "hooks": [
          {
            "type": "command",
            "command": "scripts/agent-session-start"
          }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "shell",
        "hooks": [
          {
            "type": "command",
            "command": "node .roder/hooks/check-shell.js"
          }
        ]
      }
    ]
  }
}
```

Use `.roder/hooks.json` when the policy is specifically for Roder, or copy an existing `.codex/hooks.json` when you want the same local hook behavior in both tools. Hook commands receive a JSON payload on stdin and can return `hookSpecificOutput.permissionDecision` or `hookSpecificOutput.updatedInput` for `PreToolUse`.

To use the refreshed catalogs, keep the same provider setup and choose the newer model ids through Roder's normal controls:

```sh
RODER_PROVIDER=codex RODER_MODEL=gpt-6-astra roder
RODER_PROVIDER=supergrok RODER_MODEL=grok-4.6 roder
RODER_PROVIDER=gemini RODER_MODEL=gemini-3.8-flash roder
```

No migration is required for saved threads. The release changes hook correctness, catalog availability, and multi-agent waiting behavior while preserving the existing CLI entry points.
